Macros can remove boilerplate, but they also add complexity. This lesson focuses on `macro_rules!` — Rust's declarative macro system — covering the cases where macros genuinely improve code and the pitfalls that make them dangerous when overused.

- 10 to 25 min: `macro_rules!` basics: patterns and expansion.
- 25 to 40 min: Repetition patterns (`$(...)*`, `$(...),+`).

## Key concept: macro vs function — the fundamental difference

| | **Function** | **Macro (`macro_rules!`)** |
|---|---|---|
| Operates on | **Values** at runtime | **Syntax tokens** at compile time |
| Return type | One return type | Can expand to any syntax |
| Arguments | Fixed types/arity | Variadic, any fragment kind |
| Performance | Call overhead | Zero (inlined at expansion) |
| Error messages | Clear | Often cryptic |
| Debugging | `dbg!`, print | Expand manually (`cargo expand`) |
| When to use | Default | When functions can't express it |

The canonical example: `vec![1, 2, 3]` — you can't write a regular function that accepts a comma-separated list of expressions of varying count. That requires a macro.

---

## When to use a macro

Use a macro when:

- You need to accept syntax that functions can't (identifiers, code blocks, variadic args)
- You want to generate repeated code at compile time
- You want ergonomic test helpers (like `vec![]`, `assert_eq!`)
- You need the macro to capture the caller's line/file info (`file!()`, `line!()`)

**Prefer a function** when:

- You only need to transform data at runtime
- Types and borrowing are the main concern (macros won't help with lifetime errors)
- You want good error messages

## `macro_rules!` basics

A macro rule has two parts: a **pattern** (what it matches) and a **template** (what it expands to).

```rust
macro_rules! say_hello {
    () => {
        println!("Hello, world!");
    };
}

say_hello!();   // expands to: println!("Hello, world!");
```

Call sites use `!`:

```rust
say_hello!();   // with parens
say_hello![];   // with brackets
say_hello!{};   // with braces — all valid
```

### Fragment specifiers

Macros match **token trees**, not text. Each `$name:kind` captures a specific syntax fragment:

| Specifier | Matches | Example |
|-----------|---------|---------|
| `$e:expr` | An expression | `1 + 2`, `"hello"`, `f(x)` |
| `$i:ident` | An identifier | `foo`, `my_var` |
| `$t:ty` | A type | `i32`, `Vec<String>` |
| `$p:pat` | A pattern | `Some(x)`, `Ok(_)` |
| `$s:stmt` | A statement | `let x = 1;` |
| `$tt:tt` | Any token tree | Most flexible |
| `$l:literal` | A literal | `42`, `"hello"`, `3.14` |

```rust
{% raw %}
macro_rules! debug_val {
    ($name:ident = $val:expr) => {
        println!("{} = {:?}", stringify!($name), $val);
    };
}

let x = 42;
debug_val!(x = x);  // prints: x = 42
{% endraw %}
```

## Repetition

The power of `macro_rules!` is its ability to accept variadic input through repetition syntax.

### Syntax: `$(...)*` and `$(...),+`

```
$(pattern)*       zero or more repetitions (no separator)
$(pattern),*      zero or more repetitions, comma-separated
$(pattern),+      one or more repetitions, comma-separated
$(pattern)? $(,)?  optional trailing comma
```

### Building `vec!`-like behavior

{% raw %}
```rust
macro_rules! my_vec {
    ($($e:expr),* $(,)?) => {
        {
            let mut v = Vec::new();
            $(v.push($e);)*
            v
        }
    };
}

let v = my_vec![1, 2, 3];
let v = my_vec![1, 2, 3,];  // trailing comma ok — $(,)?
```

Teaching points:

- `$($e:expr),*` matches zero or more comma-separated expressions.
- `$(v.push($e);)*` expands for each matched expression.
- The `$(,)?` makes a trailing comma optional — ergonomic.

### Summing variadic arguments

```rust
macro_rules! sum {
    ($($e:expr),* $(,)?) => {
        {
            let mut total = 0;
            $(total += ($e);)*
            total
        }
    };
}

let x = sum!(1, 2, 3, 4);  // expands to: 0 + 1 + 2 + 3 + 4
```
{% endraw %}

## Multiple patterns (dispatch)

A single macro can have multiple match arms:

{% raw %}
```rust
macro_rules! log {
    // No format args
    ($level:ident, $msg:expr) => {
        eprintln!("[{}] {}", stringify!($level), $msg);
    };
    // With format args
    ($level:ident, $fmt:literal, $($args:expr),*) => {
        eprintln!("[{}] {}", stringify!($level), format!($fmt, $($args),*));
    };
}

log!(ERROR, "connection refused");
log!(WARN, "retry {}/{}", 3, 5);
```

Match arms are tried in order — the first matching pattern wins.
{% endraw %}

## Mini-lab: validated map macro for tests

Goal: build a `map_no_dupes!` macro that constructs a `HashMap` and asserts no duplicate keys — useful in tests where you accidentally write the same key twice.

{% raw %}
```rust
use std::collections::HashMap;

macro_rules! map_no_dupes {
    ($($k:expr => $v:expr),* $(,)?) => {{
        let mut m = HashMap::new();
        $(
            let old = m.insert($k, $v);
            assert!(
                old.is_none(),
                "duplicate key in map_no_dupes!: key was {:?}",
                $k
            );
        )*
        m
    }};
}
```

Usage:

```rust
let config = map_no_dupes!(
    "host" => "localhost",
    "port" => "8080",
    "debug" => "true",
);
assert_eq!(config.get("host"), Some(&"localhost"));
```

Test the failure case:

```rust
#[test]
#[should_panic(expected = "duplicate key")]
fn map_no_dupes_panics_on_duplicate() {
    let _ = map_no_dupes!("a" => 1, "a" => 2);
}
```
{% endraw %}

Teaching points:

- The double braces `{{ ... }}` create a block that evaluates to the `HashMap`.
- Macros can embed assertions that fail fast in tests.
- Keep the macro name explicit about its invariant: `map_no_dupes` tells you exactly what it checks.

## Code walkthrough: naive → idiomatic

### Naive: repeated boilerplate in tests

```rust
#[test]
fn test_routes() {
    let mut routes = HashMap::new();
    routes.insert("/", handler_home);
    routes.insert("/about", handler_about);
    routes.insert("/contact", handler_contact);
    // ... 10 more lines
}
```

### Idiomatic: a test helper macro

{% raw %}
```rust
macro_rules! routes {
    ($($path:expr => $handler:expr),* $(,)?) => {{
        let mut m: HashMap<&'static str, fn(Request) -> Response> = HashMap::new();
        $(m.insert($path, $handler);)*
        m
    }};
}

#[test]
fn test_routes() {
    let routes = routes! {
        "/" => handler_home,
        "/about" => handler_about,
        "/contact" => handler_contact,
    };
    assert!(routes.contains_key("/"));
}
```
{% endraw %}

## Hygiene (basic intuition)

Rust macros are **hygienic**: variables created inside a macro expansion don't accidentally clash with variables at the call site.

```rust
macro_rules! double {
    ($e:expr) => {{
        let x = $e;    // 'x' here is in a different hygiene context
        x + x
    }};
}

let x = 10;
let y = double!(x);  // 'x' inside double! doesn't shadow caller's 'x'
assert_eq!(y, 20);
assert_eq!(x, 10);   // still 10
```

### Practical hygiene guideline

For variables that are deliberately "leaked" (like `m` in `map_no_dupes!`), use a block `{{ ... }}` to contain them and return the result by value. For internal temporaries, use unlikely names like `__internal_tmp`.

## Exporting macros

To use a macro outside its defining module:

```rust
// In lib.rs or the defining module:
#[macro_export]
macro_rules! map_no_dupes { ... }

// Users:
use my_crate::map_no_dupes;
// or with #[macro_use]:
#[macro_use]
extern crate my_crate;
```

`#[macro_export]` makes the macro available at the crate root.

## Debugging macros: `cargo expand`

Install `cargo-expand`:

```bash
cargo install cargo-expand
```

Then:

```bash
cargo expand    # shows all macro expansions in the crate
```

This is the best way to debug a macro that doesn't behave as expected — you see exactly what the compiler sees after expansion.

## Applications in systems programming

### Structured logging

```rust
{% raw %}
macro_rules! log_event {
    ($level:ident, $event:expr, $($k:ident = $v:expr),* $(,)?) => {
        eprintln!(
            "[{level}] event={event} {fields}",
            level = stringify!($level),
            event = $event,
            fields = {
                let mut s = String::new();
                $(s.push_str(&format!("{}={:?} ", stringify!($k), $v));)*
                s
            }
        );
    };
}

log_event!(INFO, "request_received", method = "GET", path = "/api/health", latency_ms = 42);
{% endraw %}
```

### Test fixtures

```rust
{% raw %}
macro_rules! test_case {
    ($name:ident, input = $input:expr, expected = $expected:expr) => {
        #[test]
        fn $name() {
            assert_eq!(process($input), $expected);
        }
    };
}

test_case!(empty_input, input = "", expected = Err(ParseError::Empty));
test_case!(valid_input, input = "hello", expected = Ok("HELLO".to_string()));
{% endraw %}
```

This generates named test functions from a table-like notation — much cleaner than manual parameterization.

## Challenges and extensions

1. **Procedural macros**: `macro_rules!` handles simple patterns. Procedural macros (derive macros like `#[derive(Debug)]`) work on the AST. Explore the `proc-macro2`, `syn`, and `quote` crates. When would you choose proc macros over `macro_rules!`?

2. **`assert_matches!`**: implement a macro that asserts a value matches a pattern:
   ```rust
   assert_matches!(result, Ok(x) if x > 0);
   ```

3. **`ensure!` macro**: implement a macro similar to the `anyhow::ensure!` macro:
   ```rust
   ensure!(x > 0, "x must be positive, got {}", x);
   // expands to: if !(x > 0) { return Err(format!("...")); }
   ```

4. **Debug macro tracer**: write a `trace!` macro that wraps an expression, prints the expression string and its value, and returns the value — like a verbose version of `dbg!` that includes a custom prefix.

---

## Common mistakes

1. Using macros to avoid learning ownership/borrowing (they won't help).
2. Writing large macros that are hard to debug — prefer many small macros.
3. Forgetting to parenthesize `$e` in expansions: `$e + $e` should be `($e) + ($e)` to avoid precedence issues.
4. Mixing up `*` (zero or more) and `+` (one or more) in repetition.
5. Not testing the macro itself — treat it like any other code.

## Exercises

1. Extend `map_no_dupes!` to print all duplicate keys (not just panic on the first one).
2. Write `assert_matches!(expr, pattern)` macro that panics with a helpful message.
3. Write a `vec_of_strings!(...)` macro that turns `&str` inputs into `String`s:
   ```rust
   let v = vec_of_strings!["a", "b", "c"];
   // produces Vec<String>
   ```
4. (**harder**) Write a `retry!(n, expr)` macro that evaluates `expr` (which returns `Result`) up to `n` times, returning the first `Ok` or the last `Err`.

## Recap

- Macros transform syntax; functions transform values. Use functions by default.
- `macro_rules!` matches token patterns and expands them.
- Repetition (`$(...)*`, `$(...),+`) enables variadic inputs.
- Keep macros small, tested, and documented.
- Use `cargo expand` when a macro doesn't behave as expected.
