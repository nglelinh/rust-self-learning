Traits are Rust’s primary abstraction tool for reusable code without runtime cost. This lesson teaches what traits are, how to define and implement them, and how to use trait bounds in generic functions.

## 60-minute teaching plan

- 0 to 10 min: Why traits exist: shared behavior, not shared data.
- 10 to 25 min: Define a trait and implement it for multiple types.
- 25 to 40 min: Trait bounds in generic functions.
- 40 to 55 min: Default methods and a simple "blanket impl" idea.
- 55 to 60 min: Exercises and recap.

## Learning goals

By the end of this lesson, students can:

- Define a trait with one or more methods.
- Implement a trait for multiple types.
- Use trait bounds (`T: Trait`) to write generic code.
- Use default methods to reduce boilerplate.

## What a trait is

A trait is a contract: "types that implement this trait provide these methods." It is Rust’s way to express interfaces.

## Define a small trait: `Normalize`

We will create a trait that produces a normalized string representation.

```rust
pub trait Normalize {
    fn normalize(&self) -> String;
}
```

Teaching points:

- `&self` means normalization doesn’t need to consume the value.
- Returning `String` means we produce owned output.

## Implement the trait for multiple types

### For `str` and `String`

```rust
impl Normalize for str {
    fn normalize(&self) -> String {
        self.trim().to_lowercase()
    }
}

impl Normalize for String {
    fn normalize(&self) -> String {
        self.as_str().normalize()
    }
}
```

Teaching points:

- Implementing for `str` makes it work for `&str`.
- Reuse implementations instead of duplicating logic.

### For numbers

```rust
impl Normalize for i32 {
    fn normalize(&self) -> String {
        self.to_string()
    }
}
```

Discuss: normalization for numbers is domain-specific; the point is that traits let you define "what you mean".

## Use it from a generic function

Trait bounds let you write reusable functions:

```rust
pub fn normalized_pair<A: Normalize, B: Normalize>(a: &A, b: &B) -> (String, String) {
    (a.normalize(), b.normalize())
}
```

Or with `impl Trait`:

```rust
pub fn normalized(x: &impl Normalize) -> String {
    x.normalize()
}
```

Teaching point: `impl Trait` in arguments is mostly syntax sugar for a generic bound.

## Default methods

Default methods reduce boilerplate:

```rust
pub trait Normalize {
    fn normalize(&self) -> String;

    fn normalize_nonempty(&self) -> Option<String> {
        let s = self.normalize();
        if s.is_empty() { None } else { Some(s) }
    }
}
```

Teaching points:

- Default methods can call required methods.
- This encourages small traits with composable helpers.

## Blanket impls (conceptual intro)

A blanket impl implements a trait for any type that meets a condition.

Example idea:

```rust
pub trait Describe {
    fn describe(&self) -> String;
}

impl<T: std::fmt::Debug> Describe for T {
    fn describe(&self) -> String {
        format!("{:?}", self)
    }
}
```

Instructor note: this is powerful but can confuse beginners if overused. Mention it as a capability, not as a default pattern.

## Tests

```rust
#[test]
fn normalize_str() {
    assert_eq!("  HeLLo ".normalize(), "hello".to_string());
}

#[test]
fn normalize_string() {
    let s = "  Hi ".to_string();
    assert_eq!(s.normalize(), "hi".to_string());
}
```

Teaching point: trait methods are just methods; once a trait is in scope, you can call them naturally.

## Common mistakes

1. Making one huge trait instead of several small ones.
2. Using traits when a plain function would be simpler.
3. Returning `&str` from normalization when you allocate anyway.

## Exercises

1. Add `Normalize` impl for `Option<&str>`: `None` -> empty string.
2. Write `fn normalize_all(xs: &[&dyn Normalize]) -> Vec<String>` (preview of trait objects).
3. Create a trait `Render` with a default method `render_line()`.

## Recap

- Traits model shared behavior.
- Implement traits for types to unlock generic reuse.
- Trait bounds express requirements for generic code.
- Default methods help keep traits small and ergonomic.
